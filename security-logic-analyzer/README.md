# Security Logic Analyzer

> 웹사이트 보안 점검을 위한 인지 기반 로직 분석 시스템

## 개요

**Security Logic Analyzer**는 OWASP ZAP, 브라우저 자동화(Playwright), LLM을 결합하여 웹사이트의 비즈니스 로직과 보안 메커니즘을 자동으로 분석하고 문서화하는 도구입니다.

### 핵심 특징

1. **인지학적 접근**: 인간 보안 전문가가 사이트를 분석하는 방식을 모델링
2. **계층적 메모리**: 중요도에 따라 정보를 효율적으로 관리 (Hot/Warm/Cold)
3. **LLM 기반 추론**: 관찰된 데이터로부터 내부 로직 추론
4. **점진적 학습**: 분석하면서 지식을 축적하고 가설을 검증

### 기존 도구와의 차이점

| 측면 | 기존 도구 (ZAP 등) | Security Logic Analyzer |
|------|-------------------|-------------------------|
| **목표** | 취약점 발견 | **로직 이해** + 취약점 발견 |
| **출력** | 취약점 목록 | **로직 문서** + 보안 분석 |
| **접근** | 패턴 매칭 | **추론 기반** |
| **적응성** | 정적 규칙 | **학습 및 적응** |

### 전체 구조 (3-Layer Cognitive Architecture)

```
┌─────────────────────────────────────────────────────────┐
│            Meta-Cognitive Layer (계획 및 조정)           │
│  - 분석 진행 상황 모니터링                                 │
│  - 다음 탐색 대상 결정                                     │
│  - 신뢰도 평가 및 전략 조정                                │
└─────────────────────────────────────────────────────────┘
                            ↕
┌─────────────────────────────────────────────────────────┐
│           Reasoning & Integration Layer (추론)          │
│  - LLM 기반 로직 추론                                     │
│  - 패턴 인식 및 분류                                       │
│  - 지식 그래프 구축                                        │
│  - 가설 생성 및 검증                                       │
└─────────────────────────────────────────────────────────┘
                            ↕
┌─────────────────────────────────────────────────────────┐
│              Observation Layer (데이터 수집)             │
│  ┌──────────┐  ┌──────────┐  ┌──────────┐             │
│  │ Browser  │  │ ZAP API  │  │ Traffic  │             │
│  │ Crawler  │  │ Scanner  │  │ Analyzer │             │
│  └──────────┘  └──────────┘  └──────────┘             │
└─────────────────────────────────────────────────────────┘
```

### 계층적 메모리 구조

```
┌─────────────────────────────────────┐
│   Hot Memory (작업 기억)             │  ← LLM에 직접 제공
│   - 현재 분석 중인 핵심 데이터        │  ← 완전한 원본 유지
│   - 크기: ~50-100 항목               │
└─────────────────────────────────────┘
              ↕ 승격/강등
┌─────────────────────────────────────┐
│   Warm Memory (단기 기억)            │  ← 요약된 형태
│   - 최근 관련 데이터                  │  ← 빠른 검색 가능
│   - 크기: ~500-1000 항목             │
└─────────────────────────────────────┘
              ↕ 승격/아카이브
┌─────────────────────────────────────┐
│   Cold Memory (장기 기억)            │  ← 디스크 저장
│   - 전체 수집 데이터                  │  ← 인덱스 + 압축
│   - 크기: 무제한                      │  ← 필요시 재로드
└─────────────────────────────────────┘
```

**핵심 아이디어**: 인간처럼 모든 정보를 기억하되, 중요한 것은 작업 기억에, 나머지는 필요할 때 다시 찾아봄

## 인지 프로세스 모델

### 인간 보안 전문가는 어떻게 사이트를 분석하는가?

```
1. 초기 탐색 (Reconnaissance)
   → 사이트맵, 주요 기능 파악
   → "어디에 주목해야 하나?"

2. 관찰 (Observation)
   → 각 기능 사용해보기
   → 네트워크 트래픽 관찰
   → "무엇이 일어나고 있나?"

3. 추론 (Inference)
   → 내부 로직 추측
   → "왜 이렇게 동작하나?"
   → "이 토큰은 어떻게 검증되나?"

4. 검증 (Verification)
   → 가설 테스트
   → 엣지 케이스 탐색
   → "내 추론이 맞나?"

5. 통합 (Integration)
   → 전체 그림 그리기
   → "시스템 전체는 어떻게 동작하나?"
```

**Security Logic Analyzer는 이 프로세스를 자동화합니다.**

## 주요 개념

### 1. 선택적 주의 (Selective Attention)

모든 데이터를 동등하게 취급하지 않습니다. 중요도에 따라 다르게 처리:

**High Priority** (즉시 상세 분석):
- 인증/권한 관련
- 민감 데이터 처리
- API 상태 변경 작업
- 에러 메시지

**Medium Priority** (요약하여 저장):
- 일반 비즈니스 로직
- 데이터 조회 API

**Low Priority** (인덱스만):
- 정적 리소스
- 마케팅 요소

### 2. 다층 추상화 (Multi-Level Abstraction)

```
Level 0: Raw HTTP Request/Response
Level 1: Semantic Events ("로그인 시도")
Level 2: Logic Components ("인증 시스템")
Level 3: Business Logic Model ("사용자 관리 워크플로우")
```

각 레벨은 이전 레벨보다 더 추상적이고 의미론적입니다.

### 3. LLM 활용 전략

**단순히 "분석해줘"가 아닌 체계적 접근**:

- **Multi-Agent**: Explorer, Analyst, Critic, Synthesizer
- **Few-Shot Learning**: 유사 사례 제공
- **Chain of Thought**: 단계별 추론
- **Self-Consistency**: 여러 번 물어보고 검증
- **RAG**: 보안 지식 베이스 활용

### 4. 점진적 학습 (Incremental Learning)

```
초기 탐색 → 흥미 지점 식별 → 깊이 분석 →
가설 검증 → 지식 통합 → 다음 목표 선정 → (반복)
```

한 번에 모든 것을 분석하지 않고, 중요한 부분부터 점진적으로 깊이 파고듭니다.

    - 권한 체계: RBAC (3개 역할)
    - 발견된 이슈: CSRF 토큰 누락 (결제 API)

### 시나리오 2: 특정 기능 깊이 분석

```bash
$ python analyzer.py https://app.com --focus authentication

[*] 인증 메커니즘 집중 분석...
[*] 관련 엔드포인트 8개 발견
[*] 로직 추론 중...

발견 사항:
- 로그인: POST /api/auth/login
  - bcrypt 해싱 사용 (확인됨)
  - Rate limiting 있음 (5회/분)
  - 실패 시 사용자명 노출 없음 (Good!)

- 토큰 관리:
  - Access token: 30분 (JWT)
  - Refresh token: 7일
  - Refresh 메커니즘 있음

⚠️  잠재적 이슈:
- 토큰 폐기 메커니즘 확인 필요
- 로그아웃 시 서버 측 검증 불확실
```

## FAQ

### Q: 기존 ZAP과 무엇이 다른가요?
**A**: ZAP은 "취약점"을 찾는 도구입니다. 우리는 "로직"을 이해하는 도구입니다. ZAP의 출력을 활용하되, 더 나아가 "왜 이렇게 설계되었나", "비즈니스 로직이 무엇인가"를 추론합니다.

### Q: LLM이 비용이 많이 들지 않나요?
**A**: 그래서 계층적 메모리 시스템이 중요합니다. 모든 데이터를 LLM에 넣지 않고, 중요한 것만 선택적으로 제공하여 비용을 최적화합니다.

### Q: 정확도는 어떻게 보장하나요?
**A**:
1. LLM의 추론은 관찰된 증거에 기반
2. 신뢰도 점수 제공
3. 불확실한 부분은 명시
4. 가능하면 가설 검증

### Q: 실제로 구현 가능한가요?
**A**: MVP는 4주 내에 구현 가능한 수준으로 설계했습니다. 고급 기능은 점진적으로 추가할 예정입니다.
